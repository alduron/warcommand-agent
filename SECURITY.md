# Security

## Reporting a vulnerability

Use GitHub's **Report a vulnerability** button under this repository's Security tab. That opens a
private advisory only the maintainers can see. Do not open a public issue for a security finding.

Expect an acknowledgement within 72 hours. If a fix ships, the advisory is published with credit
unless you ask otherwise.

## What is in scope

- Anything that lets one user read or act on another user's data.
- Anything that turns a device token, pairing code, or handoff token into account access.
- Anything that writes audio, a screen frame, or a key code to disk or to the network. The product
  promises none of those ever leave the machine, and a path that breaks it is a vulnerability even
  when nothing else goes wrong.
- Anything that reaches into the game process. See `../docs/design/12-security.md`.

## What is not

- SmartScreen warning on an unsigned installer. Known, and named on the download page.
- The absence of a code-signing certificate.
- Findings that require an attacker to already have the victim's Windows account.
- Reports generated by a scanner with no working proof.

## What this app deliberately does

It installs a global low-level keyboard hook and it can capture the game window. Both are stated in
`../docs/design/12-security.md` with the boundaries they respect: the hook returns immediately for
any key that is not a registered hotkey and never logs a key code at any level in any build, and no
captured frame is written to disk or sent anywhere. A report that these mechanisms exist is not a
finding; a report that one of the boundaries leaks is.
